Levels 4–5: reverse direction and parsing
-----------------------------------------

The results above cover levels 1–3 of the competition's five-level
interoperability plan in this repository.  Levels 4 (an *independent
receiver* decoding LunaLink-generated signals — PocketSDR-AFS, Ebinuma's
software-defined receiver) and 5 (navigation-data parsing cross-checks) are
maintained in the public test-vector repository, which ships all five
levels with bundled oracles and a zero-dependency validator:

   https://github.com/luar-space/lsis-afs-test-vectors

Its ``codes/`` (210 × ``codes_prnNNN.hex``), ``frames/``, ``signals/``
(12-second I/Q per PRN), and ``parsed/`` directories follow the repository
structure defined in the interoperability plan, and every vector there is
regenerable from this repository via ``scripts/export_test_vectors_all.py``.

Methodology
-----------

**L1 — Spreading code comparison**

LANS-AFS-SIM's ``icodegen()`` and ``qcodegen()`` functions were called via
a C harness (``dump_lans_codes.c``) to extract Gold-2046 and Weil-10230 codes
for PRN 1–12.  Each code was compared chip-by-chip against LunaLink's packed
PRN tables.  Both implementations use independent code generation:
LANS-AFS-SIM uses an 11-bit LFSR with a delay table; LunaLink uses
pre-computed tables generated from the LSIS V1.0 Appendix C/D parameters.

**L2 — Frame encoding comparison**

A C harness (``dump_lans_frame.c``) invokes LANS-AFS-SIM's encoding pipeline
(``generate_BCH_AFS_SF1``, ``append_CRC24``, ``encode_LDPC_AFS_SF2/SF3``,
``interleave_AFS_SF234``) with controlled payloads (all-zeros, all-ones,
alternating, boundary FID/TOI values).  The resulting 6000-symbol frames
are compared against LunaLink's ``frame_build()`` output.

**L3 — Cross-implementation signal decode**

LANS-AFS-SIM generates a 25-second composite I/Q signal at 5.115 MHz
containing 7 SVs (PRN 2–8) with Keplerian ephemeris from a lunar NRHO-like
constellation.  The signal is decimated to 1.023 MSPS (1 sample/chip), acquired with
FFT-based PCPS, despread with PLL carrier tracking, and the recovered
symbols are decoded with :func:`lunalink.afs.receive_frame`: sync search,
deinterleaving, LDPC + BCH decode, FID/TOI and WN/ITOW extraction, and
CRC-24 verification on all three subframes (``tests/test_interop_decode.py``).

Known limitations
-----------------

**Demodulation sample rate.** The L3 demodulation chain operates at
1.023 MSPS (1 sample per I-channel chip).  This decimates the composite
signal from its native bandwidth (set by AFS-Q at 5.115 Mcps), aliasing the
Q-channel pilot as broadband interference on the I channel.  Under low-SNR
conditions (2-bit ADC, multiple SVs) this aliasing degrades acquisition
sensitivity; for the clean LANS-AFS-SIM scenario it does not prevent a
correct decode.  A flight-credible receiver would operate at the composite
signal rate (≥ 10.23 MSPS) and acquire on the data-free AFS-Q pilot with
coherent integration over the secondary code period (8 ms) or longer —
receiver design beyond the demodulation needed to demonstrate cross-decode
is outside the scope of this reference implementation.
